# 服务器部署指南（Git 拉取 + Docker Compose）

本文针对当前仓库 `git@github.com:CSQ09115/-.git`，以「服务器 git clone → docker compose 启动」为主线。
仓库内包含 `backend/`（含已构建的 `admin_ui/`）与根目录 `docker-compose.yml`。

---

## 1. 前置条件

### 服务器建议

| 项目 | 最低 | 推荐 |
| --- | --- | --- |
| CPU / 内存 | 2 核 4 GB | 4 核 8 GB |
| 磁盘 | 30 GB | 50 GB 以上 |
| 系统 | Ubuntu 22.04 / Debian 12 | 同左 |

说明：镜像内置 PyTorch（CPU 版）与 ultralytics，镜像体积约 5–8 GB；识别模型约 37 MB；
植物图片、诊断图片与上传模型会持续增长，磁盘需预留空间。

### 需要开放的端口

| 端口 | 用途 | 是否对公网开放 |
| --- | --- | --- |
| 22 | SSH / git | 是（建议限制来源 IP） |
| 80 | HTTP（证书签发、跳转 HTTPS） | 是 |
| 443 | HTTPS | 是 |
| 8000 | 后端（Nginx 反代目标） | 否，建议仅本机或安全组内网 |
| 5432 | PostgreSQL | 否，compose 已仅绑定 127.0.0.1 |

### 软件版本

- Docker Engine 24+，Docker Compose v2.20+（使用 `docker compose` 子命令）
- Nginx 1.20+，Certbot（HTTPS）
- Node.js 20+ **仅在需要重新构建 admin_ui 时使用**；仓库已带构建产物，服务器部署可跳过

## 2. 在服务器上获取仓库

### 方式 A（推荐）：仓库只读 Deploy Key

Deploy Key 只对单个仓库生效、可设为只读，不占用账号级 SSH Key。

```bash
# 1) 在服务器生成专用密钥（不要设置口令，便于自动化拉取）
ssh-keygen -t ed25519 -C "flower-deploy@$(hostname)" -f ~/.ssh/flower_deploy -N ""

# 2) 输出公钥，复制到 GitHub
cat ~/.ssh/flower_deploy.pub
```

打开 GitHub 仓库 → **Settings → Deploy keys → Add deploy key**，粘贴公钥，
Title 任意（如 `prod-server`），**不要勾选 Allow write access**。

```bash
# 3) 配置 SSH 别名，避免和服务器上其他 GitHub 密钥冲突
cat >> ~/.ssh/config <<'EOF'
Host github-flower
  HostName github.com
  User git
  IdentityFile ~/.ssh/flower_deploy
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config ~/.ssh/flower_deploy

# 4) 验证（Deploy Key 会返回仓库级提示，能显示 successfully authenticated 即成功）
ssh -T git@github-flower

# 5) 克隆（显式指定目录名，避免仓库名 "-" 生成奇怪目录）
sudo mkdir -p /opt && sudo chown "$USER":"$USER" /opt
cd /opt
git clone git@github-flower:CSQ09115/-.git flower-guardian
cd flower-guardian
```

后续 `git pull` 会沿用该别名。

### 方式 B：HTTPS + Personal Access Token

```bash
cd /opt
git clone https://github.com/CSQ09115/-.git flower-guardian
# Username 填 GitHub 用户名，Password 填 PAT（不要填账号密码）
```

注意事项：

- Classic PAT 勾选 `repo`（只读可用 `public_repo` / 私有库需 `repo`）；Fine-grained PAT 给该仓库 `Contents: Read-only`。
- 不要把 token 写进 URL 或提交到仓库，避免进入 shell 历史和日志。
- 需要长期免交互拉取时，使用 `git config credential.helper store` 前请评估服务器安全。

## 4. 配置生产环境变量

在仓库根目录创建 `.env`（compose 会自动读取；该文件不要提交到 git）：

```bash
cd /opt/flower-guardian

cat > .env <<EOF
POSTGRES_PASSWORD=$(openssl rand -hex 24)
SECRET_KEY=$(openssl rand -hex 32)
ACCESS_TOKEN_EXPIRE_MINUTES=30
EOF

chmod 600 .env
cat .env
```

说明：

- **必须修改** `POSTGRES_PASSWORD` 与 `SECRET_KEY`。`SECRET_KEY` 用于 JWT 签名，泄露等于可伪造登录；更换后所有已登录用户需重新登录。
- 密码使用十六进制，避免 `@ : /` 等字符破坏 `DATABASE_URL` 连接串。
- 这里只放基础设施配置。天气、SMTP、AI、支付、QQ/微信登录、YOLO 密钥**不要写入 `.env`**，统一在后台「系统配置」写入数据库，未配置时接口返回“未配置”，不会导致服务启动失败。
- compose 中保留了可启动的占位默认值，仅用于首次试跑；正式环境务必用 `.env` 覆盖。

检查渲染结果：

```bash
docker compose config
```

## 5. 构建并启动

```bash
cd /opt/flower-guardian

# 构建后端镜像（上下文为 backend/，内部包含 admin_ui 产物）
docker compose build backend

# 启动（postgres 健康检查通过后才会启动 backend）
docker compose up -d

# 查看状态与日志
docker compose ps
docker compose logs -f backend
```

启动日志中应看到：

- `管理后台已挂载：/admin -> /app/admin_ui`
- `已创建管理员账号 admin`（仅首次）
- `Uvicorn running on http://0.0.0.0:8000`

等待健康检查变为 healthy：

```bash
docker inspect --format '{{.State.Health.Status}}' flower_backend
```

### 关于 admin_ui

- 仓库中的 `backend/admin_ui/` 是已构建好的产物，服务器无需安装 Node，直接构建镜像即可。
- 如果镜像构建报 `缺少 admin_ui/index.html`，说明拉取的代码缺少产物：在本地 `web/` 目录执行 `npm run build:admin`（会同步到 `backend/admin_ui`），提交后重新拉取。
- 当前仓库不包含 `web/` 源码；如要在服务器改前端，需额外上传 `web/` 并安装 Node 20+。

## 6. Nginx 反向代理与 HTTPS

### 6.1 安装 Nginx

```bash
sudo apt update
sudo apt install -y nginx
```

### 6.2 站点配置

`/etc/nginx/sites-available/flower-guardian`：

```nginx
server {
    listen 80;
    server_name flower.example.com;   # 换成你的域名，并先配置 A 记录指向服务器

    # 单次请求体上限：YOLO 模型最大 200MB，这里留出余量
    client_max_body_size 256m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket（/api/ws）
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 大文件上传与识别耗时接口
        proxy_read_timeout    300s;
        proxy_send_timeout    300s;
        proxy_connect_timeout 60s;

        # 关闭请求缓冲，模型上传直接流式转发给后端
        proxy_request_buffering off;
    }
}
```

启用并检查：

```bash
sudo ln -s /etc/nginx/sites-available/flower-guardian /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 6.3 申请 HTTPS 证书

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d flower.example.com
# 选择自动跳转 HTTPS（redirect）

# 验证续期
sudo certbot renew --dry-run
```

Certbot 会自动改写上面的 server 块并添加 443 监听；到期前自动续期由 systemd timer 负责。

### 6.4 防火墙

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
# 不要对外开放 8000 和 5432
```

如云厂商有安全组，同样只放行 22/80/443。

## 7. 首次启动的初始化行为

后端启动（`app/main.py` 的 lifespan）会自动执行：

1. `Base.metadata.create_all`：在空库中创建全部数据表；
2. `seed_plants`：写入 47 种植物基础数据（重复执行不会重复插入）；
3. `seed_admin_user`：**仅当 admin 不存在时**创建管理员账号：
   - 用户名 `admin`
   - 密码 `123456`
   - 邮箱 `admin@example.com`
4. 启动定时任务调度器（天气提醒等）。

> 管理员密码不会在每次重启时被重置，修改后重启仍然有效。

### 上线后必须修改默认密码

后台暂未提供改密页面，使用接口修改（登录接口为 OAuth2 表单格式）：

```bash
# 1) 登录拿 token
TOKEN=$(curl -s -X POST https://flower.example.com/api/users/login \
  -d 'username=admin&password=123456' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["access_token"])')

# 2) 修改密码（至少用一个强密码）
curl -X POST https://flower.example.com/api/users/password \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"old_password":"123456","new_password":"替换为强密码"}'
```

修改后重新登录验证；再重启一次容器确认密码未被重置。

## 9. 日常更新流程

```bash
cd /opt/flower-guardian

# 1) 拉取更新（只快进，避免服务器上产生合并提交）
git pull --ff-only

# 2) 如本次更新包含前端改动，确认 backend/admin_ui 已更新（仓库自带产物）
ls -l backend/admin_ui/index.html

# 3) 重新构建并滚动重启
docker compose build backend
docker compose up -d

# 4) 观察日志与健康状态
docker compose logs --tail=100 backend
docker inspect --format '{{.State.Health.Status}}' flower_backend
```

注意：

- 数据库结构目前依赖 `create_all`，只会建新表，**不会自动修改已有表字段**。涉及表结构变更的版本，先备份数据库再升级。
- 镜像重建不会影响命名卷中的数据；不要执行 `docker compose down -v`（会删除卷）。

## 10. 备份与恢复

### 10.1 备份

```bash
cd /opt/flower-guardian
mkdir -p backups
STAMP=$(date +%F-%H%M)

# 数据库
docker compose exec -T postgres pg_dump -U flower -d flower_guardian \
  | gzip > backups/db-$STAMP.sql.gz

# 运行时数据卷
for v in static_data yolo_uploads user_uploads; do
  docker run --rm \
    -v flower-guardian_${v}:/data:ro \
    -v "$PWD/backups":/backup \
    alpine tar czf /backup/${v}-$STAMP.tar.gz -C /data .
done

ls -lh backups/
```

建议将 `backups/` 定时同步到对象存储或其他机器。

### 10.2 恢复

```bash
cd /opt/flower-guardian

# 数据库（先停止写入）
docker compose stop backend
gunzip -c backups/db-XXXX.sql.gz | docker compose exec -T postgres psql -U flower -d flower_guardian
docker compose start backend

# 数据卷（示例：static_data）
docker compose stop backend
docker run --rm \
  -v flower-guardian_static_data:/data \
  -v "$PWD/backups":/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/static_data-XXXX.tar.gz -C /data"
docker compose start backend
```

## 11. 常见故障排查

| 现象 | 排查方向 |
| --- | --- |
| `docker compose ps` 中 backend 不断重启 | `docker compose logs --tail=200 backend`；常见为 `DATABASE_URL` 密码错误或数据库未就绪 |
| 访问 502 Bad Gateway | 后端未 healthy：`docker inspect flower_backend`、`docker compose logs backend`；确认 8000 端口有监听 |
| 上传模型返回 413 | Nginx `client_max_body_size` 未生效：`sudo nginx -t && sudo systemctl reload nginx` |
| 上传大文件 504 / 中断 | 检查 Nginx `proxy_read_timeout`、`proxy_send_timeout` 与 `proxy_request_buffering off`；检查磁盘 |
| 数据库认证失败 | `POSTGRES_PASSWORD` 变更但数据卷仍是旧密码。进入 `psql` 执行 `ALTER USER flower WITH PASSWORD '新密码';`，或删除卷重建（会丢数据） |
| `/admin/` 404 | 镜像内缺 `admin_ui`：`docker exec flower_backend ls admin_ui/index.html`；本地重新 `npm run build:admin` 后重建镜像 |
| 端口占用 | `ss -lntp \| grep -E ':8000\|:5432'`，修改 compose 映射或停止占用进程 |
| 磁盘写满 | `df -h`、`docker system df`；清理旧镜像与备份，勿删数据卷 |
| 模型加载失败 | 确认 `ultralytics` 已安装、模型文件存在：`docker exec flower_backend ls -lh models/*.pt` |

常用命令：

```bash
docker compose logs -f backend
docker compose logs --tail=200 postgres
docker inspect --format '{{json .State.Health}}' flower_backend
docker exec -it flower_backend bash
docker stats
```
